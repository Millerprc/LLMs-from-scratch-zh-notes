# 如何从技术书籍中获得最大收获

下面是我之前与读者分享的一些笔记，回答他们常问的"如何从我的《从零开始构建大语言模型》一书中获得最大收获"的问题。


当我阅读技术书籍时，也会采用类似的方法。这并非通用的万能法则，但可以作为一个有用的起点。

对于本书，我强烈建议按顺序阅读，因为每一章都依赖于前一章。对于每一章，我推荐以下步骤。

&nbsp;
### 1) 第一次阅读（离线）

我建议从头到尾通读一章，暂时不要做任何编码。第一次通读的目标是先把握整体大局。

理想情况下，我建议远离电脑来阅读章节。纸质书效果很好，但使用一台没有干扰（没有浏览器、社交媒体或电子邮件）的电子设备也可以。

我个人既读纸质书，也读电子墨水屏平板。虽然我从 2018 年就开始使用电子墨水屏平板，并一直尝试更多地在电子墨水屏上阅读，但我仍然发现纸质书能让我更专注。这也是为什么我有时会把有挑战性的或我真正想详细理解的研究论文打印出来。

我的建议是：第一次通读是一次短暂、专注的 20 分钟阅读，尽量减少干扰，不要过度思考或纠结于细节。

对感到困惑或有趣的部分做高亮或批注是可以的，但我建议在这个阶段不要去查资料。我只建议阅读，但不要运行任何代码。这一遍是为了理解整体图景。

&nbsp;
### 2) 第二次阅读（结合代码）

在第二次通读时，我建议把章节中的代码手动输入并运行。复制代码很诱人，因为重新输入工作量很大，但当我阅读其他技术书籍时，手动输入通常会让我对代码思考得更多（而不是仅仅扫一眼）。

如果我得到的结果与书中的不同，我会检查本书的 GitHub 仓库并尝试那里的代码。如果仍然得到不同的结果，我会尝试看看是否是由不同的包版本、随机种子、CPU/CUDA 等原因造成的。如果还是搞不清楚，向作者请教也不错（通过书籍论坛、公共 GitHub 仓库的 issues 或 discussions，最后的手段是邮件）。

&nbsp;
### 3) 练习

在第二次通读、手动输入并运行代码之后，通常是做练习题的好时机。这非常有助于巩固理解，或以半结构化的方式摆弄某个问题。如果练习题太难，查看解答也可以。不过，我仍然建议先认真尝试一下。

&nbsp;
### 4) 复习笔记并进一步探索

现在，在阅读章节、运行代码并完成练习之后，我建议回到前两次阅读时做的高亮和批注，看看是否仍有不清楚的地方。

这也是查找额外参考资料或快速搜索以澄清仍然存疑之处的好时机。但即使一切都已理解，再多读一些感兴趣的话题也无妨。

在这个阶段，将有用的见解、代码片段等记录下来或转移到自己喜欢的笔记应用中也很有意义。

&nbsp;
### 5) 在项目中使用这些想法

前面的步骤都是在吸收知识。现在，试试看你能否在项目中应用章节中的某些方面。或者以书中的代码作为起点，构建一个小项目。寻求灵感的话，可以看看补充材料，它们基本上是我为满足自己好奇心而做的小项目。

例如，在阅读并实现多头注意力机制和 LLM 之后，你可能会好奇采用分组查询注意力（grouped-query attention）的模型表现如何，或者 RMSNorm 与 LayerNorm 之间究竟有多大差别，等等。

也可能会有一些较小的方面对你的项目有用。例如，有时正是一些微小的细节最终很有用，比如测试显式调用 `torch.mps.manual_seed(seed)` 是否与单独使用 `torch.manual_seed(seed)` 有所不同。

不过，最终我还是希望能把这些知识用起来。这可能涉及使用章节的主要概念，但也可能是沿途学到的一些小细节，例如在我的项目中显式调用 `torch.mps.manual_seed(seed)` 而不是只调用 `torch.manual_seed(seed)` 是否真的有区别——哪怕是这样看似琐碎的事情。

&nbsp;
### 其他想法

当然，以上都不是一成不变的。如果某个主题总体上非常熟悉或很简单，而我在阅读本书时主要是为了获取后面章节的一些信息，那么略读一章是可以的（以免浪费时间）。

此外，对于没有任何代码的章节（例如介绍性的第 1 章），当然可以跳过与代码相关的步骤。

总之，希望这些建议对你有帮助。祝你阅读和学习愉快！
